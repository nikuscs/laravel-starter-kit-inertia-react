# Frontend Rules

These rules apply to all code under `resources/`.

Stack: React 19 + React Compiler, Inertia v3, TypeScript strict, Tailwind v4, Shadcn/ui, Wayfinder.

## Memoization

React Compiler handles all memoization. Don't use `useMemo()`, `useCallback()`, or `React.memo()`. Ever.

## Pages

Pages live in `resources/js/pages/`. They are Inertia route endpoints.

- Every page must have a default export — Inertia resolves pages by file path
- The file path must match the first argument of `Inertia::render()` in the controller
- Set `<Head title="..." />` on every page
- Define a `breadcrumbs` array when using `AppLayout`
- Keep pages under 50 lines. Extract heavy UI into components
- Don't put business logic in pages — they receive props and render

## Components

Custom components live in `resources/js/components/`. Shadcn primitives live in `components/ui/`.

- Don't modify files in `components/ui/` — these are generated Shadcn primitives. Compose them
- Forward `className` via `cn()` from `@/lib/utils` for composability
- Forward remaining props with `...props` on wrapper components
- Type data props with explicit interfaces — don't use inline object types
- Kebab-case filenames, PascalCase exports: `order-list.tsx` exports `OrderList`
- Extract lists, forms, and complex UI sections into their own component files

## Forms

Use Inertia's `useForm` hook for form state — not React local state.

```tsx
const { data, setData, post, processing, errors } = useForm({
    name: '',
    email: '',
});
```

For Wayfinder-powered forms, use the `Form` component with controller actions:

```tsx
<Form {...UserController.destroy.form()}>
    {({ processing, errors }) => /* fields */}
</Form>
```

- Disable submit buttons while `processing` is true
- Show validation errors using the `<InputError />` component
- Use `preserveScroll: true` for submissions that stay on the same page

## Navigation

- Use Wayfinder route helpers: `import { dashboard } from '@/routes'` then `dashboard()`
- Use Inertia `<Link href={...}>` for internal links — not `<a>` tags
- Use `router.visit()` for programmatic navigation
- Don't hardcode URL strings. Use Wayfinder helpers or route names

## Layouts

| Layout | Use for |
| --- | --- |
| `AppLayout` | Authenticated dashboard pages |
| `AuthLayout` | Login, register, password reset |
| `SettingsLayout` | User settings pages |

Wrap page content in the layout component — don't use Inertia persistent layouts:

```tsx
export default function Dashboard() {
    return (
        <AppLayout breadcrumbs={breadcrumbs}>
            <Head title="Dashboard" />
            {/* content */}
        </AppLayout>
    );
}
```

## Types

- Shared types live in `resources/js/types/`
- Type page props explicitly at the component level
- Don't duplicate server types — use what Inertia shares from the backend
- Don't use `any`. Type everything

## Auto-Generated Files

These are gitignored and auto-generated by Wayfinder. Don't edit them:

- `js/actions/` — TypeScript bindings for controller methods
- `js/routes/` — Type-safe route helper functions
- `js/wayfinder/` — Wayfinder internals

Regenerate with: `php artisan wayfinder:generate`

## Styling

- Use Tailwind v4 utility classes. Don't write custom CSS unless there is no utility for it
- Use `cn()` from `@/lib/utils` for conditional class merging
- Use the `dark:` variant for dark mode — the project supports both themes
- Use the `sidebar-border` design token for consistent border styling
- Use `tw-animate-css` for animations

## Formatting

OxLint and vite-plus handle JS/TS formatting and linting.

- `bun run lint` fixes issues automatically
- `bun run test:lint` checks without fixing
- `bun run test:types` runs `tsc --noEmit`
